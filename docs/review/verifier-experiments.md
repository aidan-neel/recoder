# Verifier experiments

`RECODER_VERIFIER_OP_BUDGET=N` enables a positive integer session-wide MCP operation budget for native verifiers (bugs, mutations and quality). Unset, zero or invalid values retain the current behavior. Reviewers and subagents are unchanged. Every request reaching the gate consumes the budget, including refused requests; per-turn limits still apply. The last allowed operation finishes gathering evidence, then interrupts the investigation and requests an answer with tools off. An interrupted first CLI prompt gets its original task and bounded, untrusted evidence back so finalization does not depend on a resumable CLI session.

Finalization uses the existing model-call and wall-clock budgets. A model that still calls tools while answering is stopped, not repeatedly resumed. Exhaustion itself supplies no verdict. Malformed/missing answers and inconclusive answers after exhaustion take the existing second-attempt queue with the op limit disabled, still bounded by the ordinary verifier limits and review budget/deadline. A bug supported only by a read also gets that full fallback. Real runtime proofs and legitimate refutations are kept. Proof checks, setup-error handling, baseline comparison and mutation semantics remain unchanged. In particular, no missing evidence or exhausted budget refutes a finding.

Instrumentation is always enabled for native verifier sessions, including the default unlimited setting. Model usage records carry `verifierSession`: `id`, `opBudget` (null when disabled), `ops` (requests reaching the gate, including refused requests), `refusals`, `prompts`, `internalTurns`, and `exhausted`. Internal turns are the CLI-exported cumulative count, not a claim that one CLI prompt is one inference. Missing exports/unreported counts stay null; if any Devin prompt lacks a turn count, the session total stays unknown. Stale exports are never reused for a later prompt. Benchmark reports expose deduplicated latest snapshots under `runs[].reviewer.verifierSessions`; consumers of raw usage must deduplicate by session id, keeping the latest snapshot rather than summing prompts. Snapshots carry counters only, never evidence or prompts. Existing usage queues drain these writes with the review's metrics.

Both experiments default off. No benchmark is needed to enable instrumentation; restart the server to load updated code before a future A/B run.

## Compact payload and one-run fast path

`RECODER_VERIFIER_COMPACT=1` independently enables a compact first attempt for normal runtime bug verifiers; unset or any other value preserves the original payload. Quality and mutation verifiers are unchanged. It can be combined with the op budget or tested separately. Benchmark server identity captures non-secret `RECODER_*` flags automatically.

The payload keeps the full finding, structured claim, intent/non-goals and skills/guidance. It removes a repeated shared setup prefix, deduplicates cited records, and includes up to three bounded excerpts with evidence ids and revisions. A relevant source excerpt is prioritized around the finding's line. Long run excerpts retain their command and assertion tail. If cited source does not already cover the anchor on the right revision, the harness preloads one small source window; that read is not an MCP operation or execution proof. Read failures and cancellation do not manufacture evidence.

When context is sufficient, the verifier is asked to create and execute a scratch assertion in one shell operation, importing the repository's real code. This is a fast path, **not a one-run limit**: all normal tools and repro repair remain available on missing context or setup failure. Candidate-specific own-run proof checks and baseline comparisons are unchanged. An inconclusive compact attempt, including a bug supported only by a trace, gets the existing second-attempt queue with the full payload and no op limit, subject to the normal review budget/deadline. A successful runtime proof or legitimate refutation needs no extra attempt. The first attempt never converts missing context or a setup failure into a refutation.
